# 云间随行 · 移动应用模板

从 index.html 进入。layouts/adaptive.html 是唯一外壳：宽度 <600 使用底栏，600–959 使用图标窄侧栏，960+ 使用完整侧栏。AppShell 移动同一 Nav，不复制菜单与状态；窄屏详情隐藏底栏并提供上级返回。

首页、客户、任务、更多是四个稳定根入口。“更多”集中订单、客户分栏工作台、记录与个人设置，避免底部堆满功能。主要交互包含查询筛选、进入详情、编辑保存、导入导出及处理结果。

## 直接复用业务 View

客户、订单、导入导出、任务、设置直接引用 ../admin/blocks/content.html 及 ../admin/views/，没有按布局复制。app.js 只定义移动导航；业务动作来自 ../admin/app.js 和 ../admin/workflows.js。manifest 列出真实共享路径。修改一个业务 View 后，后台和移动端同时生效。

这是一套客户端应用模板，不含生产登录、权限、服务端上传或推送。它明确共享后台的本机虚构数据，便于在不同外壳中验证同一内容。

## 状态与布局

- Hash 使用后台同一组具名字段：页面、资源、查询、分页、呈现、工作台面板、任务编号；导航形态由实际宿主宽度计算，不写入 Hash。完整链接恢复选择，其他浏览器没有本机任务时显示恢复入口。
- 编辑与导入草稿在一个模块中，调整宽度保留；业务导航使用现有 dirty guard。文件不放进 Hash，刷新导入页面须重新选择。
- 业务 Pane/PagedList 负责正文滚动，页首和底栏固定；列表分页仍属于列表，不混进全局底部导航。
- ui-sm/ui-lg/ui-link 和主题继承共享偏好，在“更多 → 界面偏好”保存；手机不自动使用 sm。

## AI 取用

复制适合的布局和 blocks，再挑 manifest 中的业务 View。若不需要整个后台示例，将所选共享 View 及对应动作迁入自己的系统，修改显式相对路径。layout 不含客户字段，View 不加载第二份框架。

同源静态 HTTP(S) 和 /ui 资产映射即可运行，不支持 file://。验收见 ../../ITERATION-REVIEW.md；这些是可修改模板，不是新组件协议。

返回使用可恢复的路由层级：客户列表→客户详情→编辑；编辑返回原详情（工作台发起编辑则返回工作台），再返回列表时查询仍由 Hash 恢复。页面刷新或复制链接后也能计算上一级，不依赖外部浏览历史。
