# 应用模板库

先打开 `index.html` 选择已发布系统，再进入该系统的独立首页。总入口只导航，不嵌入业务页面或预览 iframe。`manifest.json` 只列真正可运行的系统，未发布方向明确标记为计划。

## AI 从哪里开始

1. 选择最接近目标任务的系统，体验其布局版本与页面交互。
2. 阅读系统 README 和 manifest，定位布局、业务 View、状态/数据动作及必要依赖；复制适用部分。
3. 自由修改 View 的普通 HTML 和 Bootstrap 组合。使用到具体组件时读取其 YAML；State、保存、权限等必要合同仍需遵守，不要求预读无关文档。

组件是稳定能力，布局模板负责外壳，业务 View 负责内容，blocks 是可修改的应用区块。不要把详情页等任意编排需求塞进一个 schema 组件。

## 当前可用

- `systems/admin/`：后台管理，侧栏/顶部/混合导航；共享客户、订单、设置、操作记录、状态恢复和源码指南页面。
- `systems/mobile/`：自适应底栏/窄侧栏/完整侧栏，直接复用后台同一组业务 View；移动根导航、详情返回与表单保存。
- `systems/desktop/`：资源分栏/窄屏列表抽屉，共用笔记编辑、待办及保存历史 View；多草稿、统一保存、编辑/分屏/预览。

目录支持场景关键词、应用类型筛选，并提供运行截图、布局数量、manifest 和取用说明。先体验相似系统，再复制布局与业务文件。

## 运行与边界

模板由普通 HTML/JS 和 View 组成，在同源静态 HTTP(S) 服务中运行，不需要业务服务器或服务端渲染。当前资源路径以 /ui 开头，需要将本目录与框架资产映射到 /ui；file:// 双击不属于受支持的模块预览方式。

原先的 customer-workspace、customer-detail、settings-console、records-table、note-studio、content-catalog 单页范例保留为独立参考；写作场景已整理为 desktop 系统，内容系统尚待迁移。单页链接不作为新的系统导航入口。
