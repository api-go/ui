# 下一轮：移动交互基础能力

目标：在现有共享 View 上补齐真正的移动交互，而不是新增一组只换导航的布局。继续 Bootstrap First、同一数据源/草稿、插槽、Hash 恢复；不修改 State。

1. **通用模态抽屉与 ActionSheet**：优先复用 Bootstrap Offcanvas，明确打开/关闭/取消/返回值、焦点、遮罩、返回键、嵌套与卸载。与保留多资源草稿的 SidePanel 区分职责，不改变既有设计。先做商品选择和预约操作两个真实消费者。
2. **加载更多与刷新**：先审查 ListDataSource，复用现有请求适配器，补首屏/下一页/刷新/重试/取消及重复触发保护。下拉手势只有真实必要时才增加，不在页面另造请求队列。
3. **滑动操作与恢复**：用消息/工单验证 SwipeActions 的横纵手势边界、可见按钮替代、误触/取消；同时检查安全区、软键盘、返回、列表查询和滚动恢复。平台权限与原生小程序接口留在单独适配轨道。

执行顺序是合同与最小消费者→组件/模板→原生触摸和键盘任务→验收→沉淀 SOP。每项通过后再进入下一项；不需要为常规实现逐项征询。若确实需要 State 或非 UI 框架调整，先保留证据并沟通，继续独立任务。

验收：320/390/平板/桌面，default/ui-sm/ui-lg，普通/ui-link，浅/深；还须覆盖动画中取消、旋转/缩放、卸载、失败重试、焦点返回和复制链接/刷新恢复。协议和几何通过不能替代人工看图、真实操作及完整业务闭环。

本文件是下一轮计划，不把这些未实现能力计入上一轮交付。生产上传适配、复杂排班、保存查询、媒体裁剪继续保留独立条目。
