# 云间工作台：后台管理系统模板

从 `index.html` 进入系统。选择侧栏、顶部或混合导航，体验同一套客户、订单和设置页面。

本次增加客户导入、导出、任务列表和逐项结果及分步创建五个 View，当前共18个 View。列表页首“数据操作”进入导入/导出/分步创建，主导航“任务与结果”查看最近30次本机结果；移动模板直接复用这些文件。

导入支持 UTF-8 JSON 对象数组（1MB/200行/30列上限），使用原生文件控件和 JSON.parse，不自行实现 CSV/Excel 解析。字段映射后直接绑定一份行草稿，支持勾选跳过、重复邮箱/必填/格式校验、行内修正、确认及失败重试。步骤保存在 adminImportStep，文件及修正不放URL，刷新须重新选择文件；跨布局保留草稿。生产 CSV/Excel 使用 Table 所属导入 API。

导出范围是列表当前页（沿用已应用查询/排序）或全部客户，可选字段，实际下载 JSON。结果保存生成时的快照，再次下载不重查。批量跟进结果区分完成、无需更新及记录失效；无效任务ID显示恢复入口。它们没有模拟后台任务或服务器上传进度。

## AI 取用路径

1. 看系统交互和 `manifest.json`，选择相似页面及布局。
2. 复制入口和所选 `layouts/*.html`、需要的 `views/` 与 `blocks/`；按需删除无关路由和依赖。布局只处理外壳，业务 View 可以自由改 HTML。
3. `app.js` 提供一份系统状态、路由配置、schema 和操作函数；`data/fixtures.js` 是虚构数据。页面直接绑定状态，不使用通用详情 schema。
4. 接入业务时替换本地保存动作，使用现有领域 API 做权限、校验和事务；服务器确认后再清除 dirty。按需读取具体组件 YAML，避免通读无关文档。

## 组合边界

入口统一加载依赖；布局、导航区块、内容区块和业务页面都由已有 View 加载。三个布局引用同一个 `blocks/content.html`，这里用静态 View 文件路径和 Hash 条件选择页面。没有新的通用路由器、渲染 DSL 或 View 脚本注入器。

业务 View 是 HTML 片段，无 html/body、独立 viewport 或重复脚本。所有脚本在入口执行一次，避开 View 的文档级脚本去重和全局作用域限制。布局切换会重建外壳 DOM，但草稿、查询和数据源仍由系统持有，因此不丢编辑值。

布局/区块/页面的加载失败通过 View 的 error/ready 事件反馈到入口。入口仅保存公开 View 实例供 load() 重试，不读取组件内部 DOM 或修补 State；切换路由清除已过时的失败提示。

Pane 负责固定页首；内容 View 的普通正文自身滚动，PagedList 的正文内部滚动，工具与分页固定。每个方向只有一个正文滚动所有者。

## 本地数据与导航

- 保存、关注、订单状态和操作记录写入 `LocalStorage.adminTemplateData`。刷新读回；重置只替换这个键。主题单独存于 `adminTemplateDark`。
- 这不是实际 CRM、认证或支付服务。页面展示的保存、通知偏好和订单状态都明确属于本机示例。
- Hash 的 adminLayout/adminPage/adminId 恢复布局、页面和资源；adminCustomers/adminOrders 恢复各自的搜索、筛选、排序、页码和页长。列表仍只有一个 ListDataSource；不再复制一份模块查询状态。
- 布局切换保留草稿。系统导航离开未保存编辑前确认；浏览器后退保留草稿并提供“继续编辑”，不会静默覆盖另一个客户的草稿。
- 校验失败与保存失败都保留草稿。“状态与恢复”可模拟下一次本地保存失败并重试，或确认重置全部示例数据。

## 预览与扩展

通过提供 `/ui/` 资源的静态 HTTP(S) 服务访问，不需要业务后端。当前入口用绝对 /ui 路径，部署到子路径时按宿主调整静态映射或资源路径，不修改 State。

`manifest.json` 列出布局、全部页面、交互与依赖。顶部/侧栏导航来自同一组配置。添加新的业务段落直接编辑对应 View；只有稳定且跨场景复用的交互缺口才新增组件。

本轮验收与限制记录见 `ASSESSMENT.md`。

## 可继承的工作台组合

新增“客户工作台”复用 `views/customers/list.html` 与 `detail.html`。外层 AppShell 负责系统导航；SplitPane 负责列表/详情及自动 Resizer；每个 Pane 只有一个滚动所有者。桌面默认列表宽度 520，拖动或键盘调整后写入 `LocalStorage.adminCustomerListWidth`；手机切换浏览/详情时保留两个区域。

Hash 字段与所有权：

| 字段 | 恢复内容 |
| --- | --- |
| adminLayout / adminPage | 外壳布局及当前页面 |
| adminId | 独立详情/编辑的资源身份 |
| adminCustomers / adminOrders | 各列表已应用关键词、条件、排序、页码及页长 |
| adminWorkspaceCustomer | 工作台正在查看的客户，独立于批量勾选 |
| adminCustomerPane | 窄屏浏览/详情；未指定时按是否已有客户选择推导 |
| adminCustomerView | list / cards，两种呈现复用同一数据源及查询 |
| adminHistory | 已应用操作记录搜索；输入草稿只留在模块状态 |
| adminReturn | 编辑后返回工作台的上下文，刷新编辑地址仍可正确返回 |

列表/卡片设置使用 Pagination 的 settings 插槽，保留内置页长设置。资源选择和面板变化用 Hash.go 合并，不覆盖无关路由字段。复制链接恢复的是 UI/资源标识，不会复制本地记录或取得权限；记录不存在时显示恢复入口。未保存字段和请求/勾选等临时状态不进入分享地址。

对照 Table 模块，已沉淀的能力是：导航/资源 Hash、可调分栏与持久宽度、移动端单面板、同源数据驱动列表/详情、条件查询与呈现恢复、AutoForm 保存与取消、选择动作插槽、错误保留与重试。导入/导出、备份恢复、SQL/图表分析和服务端保存的分析 View 属于后续领域模板，应接真实 API，不在这个本机客户示例里重建服务端原语。

翻译遵循 master 既有自动翻译及文件生成机制：只维护 `{#...#}` 标记，不附加本地词典。记录本身的名称、城市、枚举身份等数据与界面标签分开。

分步创建采用 AutoForm 和同一份 customerDraft，分基本资料、合作信息及核对保存；退回和切换布局保留输入。adminCreateStep 只恢复步骤，缺少未保存数据时回第一步。它作为独立流程示例存在；常用“新建客户”仍是一次填写的表单。


导航实现：Nav 共用 list/value/nav 数据协议；顶部按实际可用宽度溢出到更多，不换行。侧栏透明填满宿主，AppShell 内部用 SplitPane/Resizer 管理持久宽度和窄屏抽屉。客户分栏同样复用 SplitPane 的列表图标与抽屉，不维护另一份面板菜单。移动宿主通过 templateHost.headerBack 声明全局返回，避免共享 View 重复显示常规返回入口。
